How 26.1 fits together

Task
Manage testing for several teams in one place: isolated test libraries and launches per team, but unified portfolio status for leadership — no mixing, no leaks.
How
An organization groups projects (streams). Each stream has its own Test Case Library, Milestones, Test Plans, and execution results — manual launches, automated and agentic test runs all coexist in one place per stream. Access control sits at the org level — manage who sees which stream. MCP then fetches and aggregates results across streams to build a unified portfolio visualization.
Result
Each team owns their test cases and results independently — manual launches, automated and agentic test runs stay isolated per stream. Leadership gets a single portfolio visualization across the org: overall status, per-project breakdown, risk identification — without access leaks.

Explore your organization

Task
Organize multiple independent projects within one organization — invite teammates if you want, but you can go solo.
How
After sign-in, open your dedicated organization (not Personal) from All Organizations. In the sidebar, Projects is where you see and create streams (A, B, C, and more). Organization users lets you invite colleagues and grant per-project access — but this is optional. All project management happens in one place.
Result
You can create and manage as many projects as you need, each with isolated test libraries and results. Inviting teammates is optional — you can complete the entire playbook solo if you prefer. Team access can be added anytime.

Want to invite a colleague?

From the sidebar, open Organization users → Invite user / Assign user. Grant them access to Stream A and Stream B now (you'll grant Stream C access after you create that project). Set View only or Can edit per project. They appear in the list after they follow the invite link.

Manual launches

Task
See a finished session in A/B, then start your own loyalty launch in Stream C.
How
Open Manual Launches in Stream A or B (filter by Demo if names use that prefix). A launch is a session on a plan: per-case status, comments, attachments. Stream B smoke should show TMS-BOOK-010 / 013 as Passed. Stream A keeps failure evidence on TMS-BOOK-002; Stream B on TMS-BOOK-018. Mobile smoke in A often leaves TMS-MOB-001 as TO_RUN — mark it Passed with a short comment if you want statistics to move. Then in Stream C start a manual launch from Loyalty smoke and execute TMS-LOY-001.
Result
You have walked Library → Plan → Launch once by hand. MCP will repeat that path with more cases.

Connect to the remote MCP server

Task
Connect an AI assistant to this beta instance so it can read Stream A/B and create Stream C artifacts for you.
How
An API key is required for MCP server. Generate it after login: avatar → My Profile → API Keys → Generate API Key (for example mcp-beta). Copy it immediately — it is shown only once. Token steps: How to get an access token. Detailed MCP server documentation: reportportal/reportportal-mcp-server. Endpoint: https://tms.beta.reportportal.io/mcp.
Result
The assistant can call TMS tools on your org.

Cursor — mcp.json

Settings → Customize → MCP → Add Custom MCP. Paste the block below.
Omit X-Project here so the agent can query Stream A, Stream B, and Stream C via projectKey (pattern: your-org-slug.stream-a — You can find it in the general project settings). 

{
  "mcpServers": {
    "ReportPortal": {
      "url": "https://tms.beta.reportportal.io/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}

Replace YOUR_API_KEY with the key from Profile. When the server is connected, ask: “What ReportPortal tools are available?”

Portfolio dashboard (MCP)

Task
While the central view for automated and manual tests is still in development, get a single quality picture for the whole organization.
How
Build the dashboard with MCP: combine data across Stream A, Stream B, and Stream C. Skill reportportal-release-quality and prompt portfolio-dashboard.md. Keep Manual, Automated, and Agentic as separate lines — do not blend them into one org pass rate.
Result
A Go / Go with conditions / No-go with risks. Stream A should show agentic + search automated tests + mobile manual. Stream B checkout/payment. Stream C looks thin until you add cases and a launch — that gap is useful. 
Using the ReportPortal MCP server, build a portfolio dashboard
across projects in my beta organization (Stream A, Stream B, and Stream C if it exists).

Include:
- Manual — Test Plans / Manual Launches
- Automated — automated test launches
- Agentic — AI agent / CheckSuite results

Requirements:
1. Aggregate quality status across projects
2. Break down by testing type: Manual / Automated / Agentic
3. Highlight top risks and incomplete areas
4. Show what looks healthy vs what needs attention
5. Give a clear GO / NO-GO recommendation with next actions
6. Format as a dashboard-style view with a short executive summary (use Canvas when available)

Metric rules:
- Do not blend Manual + Automated + Agentic into one org pass rate
- Automated / Agentic: evaluate the latest suite or CheckSuite only (status, freshness, PB/TI)
- Manual: use plan coverage (covered/total) and open TO_RUN, not lifetime pass % across all demo launches
- Split defects by intent: PB (blocks) · TI (classify) · AB/SI (test debt)
- Gate = explicit checklist; GO only if all criteria pass

Widgets:
- Gate readiness donut
- Defect mix
- Freshness vs SLA
- Testing-type health bars
- Automated tests stacked charts
- Manual coverage + TO_RUN backlog
- Agentic latest-status donut
- Prioritized next actions

Tips

  • All demo data is synthetic (TravelBook — Barcelona, Paris, Lisbon, etc.).
  • Stable identifiers are TMS-BOOK-* and TMS-MOB-* in the case name, not folder numbers.
  • Project key format is organization-slug.project-slug (read it from the URL).
  • Duplicating a test plan deep-copies cases into the library — expect extra copies if you try that.
  • Automated tests for Search & Filters: e2e-playwright-tests.
  • Questions: contact your ReportPortal representative and mention the 26.1 Beta Playbook.
