26.1 Beta Playbook

Try the new Organizations model and Test Management (TMS) on a synthetic hotel-booking product. Your organization already contains Stream A and Stream B. You will create Stream C, add test cases, run TMS via MCP, and build a cross-project quality dashboard.

Instance: tms.beta.reportportal.io Product: TravelBook Repo: 26.1-beta-testing

Open your organization

26.1 groups projects inside an organization so each stream / team keeps its own results and access, while a Test Lead can still roll quality up across the org.

  1. Open All Organizations
    After sign-in you land on All Organizations. Each tile is a separate org. Personal orgs show a person icon.
  2. Open the organization you were given for beta
    Ignore Personal tiles unless you want a sandbox of your own. The TravelBook dataset lives in the dedicated org.
  3. Check the sidebar
    Confirm Projects and Organization users are available.

Create Stream C and add test cases

Stream C is empty on purpose. Create it as a third team (for example Loyalty & Reviews) so the organization has three projects before you build the portfolio dashboard.

  1. Create the project
    In your organization open Projects → Create project. Name it Stream C. Open it and join / assign yourself if prompted.
  2. Open Test Case Library
    From the project sidebar open Test Case Library → create a folder Loyalty & Reviews.
  3. Create two cases in the UI (copy the names so later MCP steps stay consistent):
    Suggested nameTypeWhat to put in the scenario
    [TMS-LOY-001] Earn loyalty points after a confirmed booking Text After booking BK-2026-004521, the traveler’s loyalty balance increases by the stay’s point value.
    [TMS-LOY-002] Redeem points at checkout Steps Open checkout → apply points → total decreases → remaining cash amount is shown.
  4. Open a case and confirm name, tags (e.g. loyalty), and scenario type. You will add more cases via MCP in TMS via MCP.

Assign a user to the organization and projects

User management is organization-scoped: one place to invite a colleague and set access per project.

  1. In your organization open Organization users.
  2. Click Invite user / Assign user and enter a colleague’s email.
  3. Keep the organization role as Member.
  4. Add Stream A, Stream B, and Stream C. Set View only or Can edit per project.
  5. Confirm. The user appears in the list only after they follow the invite link.

Part 1 — Test Case Library

The library is the source of truth for manual scenarios. Open Stream A first, then repeat in Stream B.

  1. Open Stream A → Test Case Library
    Browse Search & Filters, then open [TMS-BOOK-001] Search hotels by destination city. This is a Steps scenario — an ordered checklist.
  2. Compare a Text scenario
    Open [TMS-BOOK-004] Sort hotel results by lowest price (instructions + expected result, no step list).
  3. Switch to Stream B (All Organizations → your org → Stream B → Test Case Library).
    Open [TMS-BOOK-010] Select room and proceed to checkout and [TMS-BOOK-013] Complete payment with valid credit card.
  4. Notice tags and requirements
    Smoke / regression / payment / agentic_candidate tags are on the case. Some cases also have linked requirements in the detail panel.

Part 2 — Milestones & Test Plans

  2. Open a milestone and note linked plans and coverage (covered / total).

Part 3 — Manual launches

A manual launch is a test session linked to a plan: per-case status, comments, attachments. Filter the launch list by Demo if pre-seeded names use that prefix.

  1. Open Manual Launches in Stream A or Stream B.
  2. Click a launch → executions are grouped by folder.
  3. Open an execution to mark status, add a comment, or attach a screenshot.
  4. Check the launch sidebar for attributes such as product:TravelBook.

What to look for

Clean smoke

Stream B — a smoke launch where TMS-BOOK-010 / 013 are Passed.

Failures with evidence

Stream A — TMS-BOOK-002 failed with a comment / attachment. Stream B — TMS-BOOK-018 expired promo.

TO_RUN for practice

Stream A mobile launch is designed so you can execute TMS-MOB-001 yourself and watch statistics update.

Regression history

Several launches on TMS-BOOK-002 (failed → failed → passed) show how a flaky filter was tracked.

Guided tours (about 15 minutes each)

A

Tour A — Smoke happy path (beginner)

  1. Stream B → Library → open TMS-BOOK-010 (room selection steps).
  2. Milestones → find the checkout / payments milestone → note the smoke or checkout plan.
  3. Test Plans → open the smoke / happy-path plan → confirm TMS-BOOK-010 and TMS-BOOK-013 are listed.
  4. Manual Launches → open the pre-release smoke launch → confirm those cases passed.
  5. Open the TMS-BOOK-013 execution and review payment steps.

Takeaway: Library → Plan → Launch on a single happy path — now split into Stream B.

B

Tour B — Failure analysis (intermediate)

  1. Stream A → Library → TMS-BOOK-002 → read the scenario and tags.
  2. Manual Launches → find a regression or filter-history launch → execution Failed with comment / screenshot.
  3. Compare later runs of the same ID if several history launches exist (failed → passed after fix).
  4. Stream B → Payment Failures / hotfix launch → TMS-BOOK-018.

Takeaway: TMS keeps failure context — comments, attachments, and history — across streams.

C

Tour C — Stream C hands-on + live execution

  1. Finish Create Stream C if you have not already (project + two loyalty cases).
  2. Stream A → Manual Launches → mobile smoke → execute TMS-MOB-001: set Passed and add a short comment.
  3. Optional: mark steps on TMS-MOB-002 one by one.
  4. Return to Stream C library and confirm your new cases are still there — this org is yours to edit.

Takeaway: Preloaded streams plus a project you created yourself — the Organizations model in one session.

Configure the ReportPortal MCP server

You do not need an API key to use ReportPortal in the browser. Login is enough for Organizations, the Test Case Library, plans, and manual launches.

An API key is only for the AI assistant (Cursor, GitHub Copilot, Claude Desktop, and similar). That tool is a separate app: it cannot see that you are already signed in in Chrome. The key is a personal pass that tells ReportPortal “this request is from me — show my organization and let me create cases.” Without it the assistant cannot read Stream A/B or create Stream C artifacts on your behalf.

Who creates the key? You generate it yourself after login. ReportPortal does not issue a shared key with the invitation. Open your avatar → Profile → API Keys → Generate API Key. Give it a name (for example mcp-beta), copy the value immediately — it is shown only once — and store it like a password. Official steps: How to get an access token.

The MCP endpoint on this instance is https://tms.beta.reportportal.io/mcp. Full client setup: MCP Server documentation.

Cursor — mcp.json

Settings → Tools & MCP → Add Custom MCP. Paste the block below. Omit X-Project so the agent can query Stream A, Stream B, and Stream C via projectKey (pattern: your-org-slug.stream-a — copy it from the project URL after you open the project). 

{
  "mcpServers": {
    "ReportPortal": {
      "type": "http",
      "url": "https://tms.beta.reportportal.io/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_API_KEY"
      }
    }
  }
}

Replace YOUR_API_KEY with the key from Profile. Do not commit it to git or paste it into a shared chat. Confirm the server is connected, then ask: “What ReportPortal tools are available?”

TMS + MCP skills — cases, planning, launches

With MCP connected, run this in Stream C (the project you created). The agent should use tools such as create_folder, create_test_case, create_milestone, create_test_plan, add_test_cases_to_test_plan, and create_manual_launch.

Paste the prompt below. Replace the project key with yours.

Use the ReportPortal MCP server on projectKey "<your-org-slug>.stream-c".

1. Find or create folder "Loyalty & Reviews".
2. Create a STEPS test case named
   "[TMS-LOY-003] Filter hotels by guest review score"
   with tags loyalty, reviews, regression.
   Steps: open search results → set review score 8+ → apply → only matching hotels remain.
3. Create milestone "Sprint 26 — Loyalty" (type SPRINT, status TESTING)
   with start/end dates this month.
4. Create test plan "Loyalty smoke" on that milestone and add
   TMS-LOY-001, TMS-LOY-002 (if they exist) and TMS-LOY-003.
5. Create a manual launch "Stream C — Loyalty smoke" from that plan,
   including those test-case IDs, started now.

Then tell me the folder id, case ids, milestone id, plan id, and launch id.
Verify in the UI Stream C → Library should show TMS-LOY-003. Milestones / Test Plans / Manual Launches should show the new sprint, plan, and launch. Open the launch and set one execution to Passed.

Portfolio dashboard (MCP)

There is no single built-in screen for Manual + Automation + Agentic across every project. With MCP you ask the agent to roll the organization up into a decision dashboard.

In this repo: Cursor skill .cursor/skills/reportportal-release-quality/ and portable prompt prompts/release-quality-dashboard.md.

  1. Stay in your dedicated organization (Stream A, Stream B, and Stream C).
  2. In an agent with ReportPortal MCP connected, paste the prompt below (or trigger the skill).
  3. Review Manual / Automation / Agentic, risks, and a Go / Go with conditions / No-go.
Using the ReportPortal MCP server, build a release quality portfolio dashboard
across projects in my beta organization (Stream A, Stream B, and Stream C if it exists).

Include Manual (Test Plans / Manual Launches), Automation, and Agentic results if available.

Aggregate quality across projects, break down by project and testing type,
highlight top risks, and give a Go / Go with conditions / No-go recommendation
with next actions.

Do not blend Manual + Automation + Agentic into one org pass rate.
Format as a dashboard-style overview with a short executive summary.
What “good” looks like Stream A should contribute agentic + search automation + mobile manual. Stream B should contribute checkout/payment manual + automation. Stream C will look thin until you add cases and a launch — that gap is useful: the dashboard should call out incomplete streams.

Tips

  • All demo data is synthetic (TravelBook — Barcelona, Paris, Lisbon, etc.).
  • Stable identifiers are TMS-BOOK-* and TMS-MOB-* in the case name, not folder numbers.
  • Project key format is organization-slug.project-slug (read it from the URL).
  • Duplicating a test plan deep-copies cases into the library — expect extra copies if you try that.
  • Autotests for Search & Filters: booking-playwright-rp/ in this repository.
  • Questions: contact your ReportPortal representative and mention the 26.1 Beta Playbook.
